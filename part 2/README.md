# Part 2 - Nutanix Calm deployment assets

This directory contains the deployment scripts, Day 2 action helpers, runbook
request scripts, and checklist for deploying the polling application as two
Calm services:

1. A PostgreSQL VM
2. A Go polling-application VM

The scripts are intentionally parameterized. Configure the values as Calm
runtime variables or secret variables after the Remote PC account, project,
cluster, subnet, and VM image are known. Do not commit passwords, JWT secrets,
GitHub tokens, or private keys.

## Calm service mapping

### PostgreSQL service

Attach `postgres/setup.sh` as the package-install or first-boot action. It
installs PostgreSQL, creates the application role and database, configures
remote access for the backend CIDR, applies `schema.sql`, and enables the
service. Attach `postgres/cleanup.sh` as an SSH service/profile action.

Required values:

- `DB_PASSWORD` (secret)
- `BACKEND_CIDR`
- `SCHEMA_FILE` or a path to the checked-out `schema.sql`

The database name and user are fixed as `poll_app`, and PostgreSQL uses port
`5432`.

### Backend service

Attach `backend/install.sh` as the package-install action. It installs the
build tools, clones the GitHub repository, builds the packaged frontend and
backend, creates a systemd service, and starts it. Set `DB_HOST` from the
PostgreSQL service IP using the Calm service-IP macro.

Required values:

- `APP_REPOSITORY_URL`
- `APP_REF`
- `DB_HOST`
- `DB_PASSWORD` (secret)
- `JWT_SECRET` (secret)
- `APP_PORT`

The backend uses database `poll_app` on port `5432` with SSL mode `disable`.

If the Calm Package Install task uses a wrapper script, pass the Calm
variables into the installer before invoking `install.sh`:

```bash
export APP_REPOSITORY_URL="@@{APP_REPOSITORY_URL}@@"
export DB_HOST="@@{DB_HOST}@@"
export DB_PASSWORD="@@{DB_PASSWORD}@@"
export JWT_SECRET="@@{JWT_SECRET}@@"
exec /path/to/install.sh
```

Create `DB_PASSWORD` and `JWT_SECRET` as Calm secret variables; keep the JWT
value stable across deployments. Configure the Self Service `DB_HOST`
variable to resolve to the exact PostgreSQL service address macro generated by
the Calm Blueprint editor, such as `@@{Postgres.address}@@`. Do not add these
Calm macros directly to `install.sh`; that script is intentionally reusable
with ordinary environment variables.

Attach `backend/restart.sh` as an optional backend service action and
`backend/healthcheck.sh` as a validation action or deployment verification
step.

## Day 2 actions and runbooks

- `actions/clear-all-data-api.sh` logs in with the seeded
  `service_account` and calls `POST /api/admin/clear-data`. It removes polls,
  options, and votes while preserving user accounts.
- `postgres/cleanup.sh` supports `MODE=votes` to remove only votes and
  `MODE=all` to remove all poll data directly through PostgreSQL.
- `runbooks/add-poll.sh` takes a title, description, and comma-separated
  options, then creates a poll through the API.
- `runbooks/vote.sh` takes a poll ID and option ID, then submits a vote through
  the API.

Store API credentials as Calm secret variables. The runbook scripts accept
either a pre-issued `API_TOKEN` or login credentials and never print the
token.

## Important deployment notes

- The backend does not run database migrations. PostgreSQL setup must apply
  `schema.sql` before the backend starts.
- The backend VM needs access to the PostgreSQL VM on `DB_PORT`.
- The PostgreSQL VM must not allow the database port from unrestricted
  networks. Set `BACKEND_CIDR` to the backend service subnet or VM address.
- Use a stable Calm secret for `JWT_SECRET`; changing it invalidates existing
  tokens.
- The repository must be reachable from the backend VM. A private GitHub
  repository is acceptable when Calm has a securely stored deploy key or
  token.
- These scripts use `bash`, `curl`, `psql`, `systemctl`, and common package
  managers. Confirm the selected Calm image provides them or install them in
  the package action.
